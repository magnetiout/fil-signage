# FIL Signage operations

Fork baseline: ScreenTinker v3.0.1 (`9794e83aed77983fe5070fe1bd1ac44046ea22d7`). Keep Node >=22.14, SQLite and the pinned lockfile. Native Android: Java17, SDK34, Gradle8.5, minSDK23. No player licence or paid kiosk dependency is needed. Billing and OTA are disabled by documented configuration. Optional hosted integrations are not configured.

## Local setup and use

`cd server && npm ci` installs the lockfile. Set a private environment file using `deploy/fil/production.env.example`; change DATA_DIR, APP_URL, port and bind for your own environment. Run with `node --env-file=/absolute/private/runtime.env server.js` or a dedicated systemd unit. First registration creates the administrator even when DISABLE_REGISTRATION=true; perform this through loopback before exposing the instance. Use a unique generated password; keep credentials out of logs/history and rotate through Settings. Back up the generated JWT secret.

The installed MINIX service is controlled with `scripts/fil/localctl start|stop|restart|status|logs|backup`. It binds loopback by default. A physical player needs an address reachable from that device; `localhost` on Android points to Android itself. Do not enter real admin credentials over public HTTP.

Generate synthetic media with `python3 scripts/fil/generate-demo.py /private/demo-assets`. Pillow10+ and ffmpeg are required; use a project virtualenv if Pillow is absent. Seed only an explicitly selected disposable/demo workspace:

```bash
DATA_DIR=/absolute/data SELF_HOSTED=true FIL_DEMO_WORKSPACE=workspace-id \
 FIL_DEMO_ASSETS=/private/demo-assets node server/scripts/seed-fil-demo.js
```

It inserts 8 original media files, 2 published playlists and 1 menu using deterministic IDs; repeated execution preserves edits and does not create devices. All contact text is synthetic. PNG artwork/text and MP4 animations are generated by this repository; no stock imagery, external fonts or customer data are distributed. DejaVu Sans is rasterized from the operating system and not bundled.

## Publishing and rollback

Create a menu under Kiosk, edit categories, parents/order, active flags, page text, gallery/video media and colours. Save changes as a draft; Publish creates a new immutable SHA256 document. Preview renders the same model and embedded assets through a five-minute page-only grant. HTML text uses textContent and escaped JSON. Only explicitly allowed HTTPS hosts can load in sandboxed external frames, with no native JavaScript bridge, downloads, intents or top-level navigation. External websites require connectivity and may refuse framing.

Menus contain at most150 items, 12 assets per item and 20MiB of unique local media (about27MiB encoded; Android download cap32MiB). This bounds memory/disk on tablets. A publication embeds local page/image/video assets, so it works offline without a service worker. External pages are explicitly outside the offline guarantee. Publication history can activate a previous version after checking its saved checksum; changing the draft never replaces the active publication.

Select a paired device, choose TV `signage_only` or tablet `hybrid_kiosk`, choose idle/warning seconds and apply. Defaults are60s +10s. Ordinary groups are management groups, not synchronized playback. Walls and synchronized groups receive signage_only.

The tablet consumes the entire first gesture, stops signage sound and holds its playlist. Only actual touch starts/resets idle; managed video pauses the timer until it ends, with a15-minute cap. A warning touch resumes the session. Timeout, Return to signage, backgrounding and activity destruction destroy the visitor WebView and clear cookies/forms/history/site storage, preserving downloaded publications. On return the latest valid schedule is applied and playlist advancement resumes. Normal menu updates wait until the session ends; upstream emergency interruptions take priority.

Local image/video signage updates also stage a complete generation before changing playback/cold-start state. Dedicated copies protect active/previous bytes from replacement in the general download cache. Incomplete updates preserve the previous generation, including across process restart. One generation is limited to512MiB and requires128MiB headroom; remote streams/widgets keep their upstream availability limits. Walls/synchronized modes retain upstream clock policy.

The panel's reported applied version comes from an authenticated device event after local verification/adoption. Saving a DB row is never proof that a physical screen applied it. Download failures appear through existing kiosk incidents; no fake online devices are created.

## Android package

ApplicationId `com.fil.signage.player` is separate from upstream. Classes retain the upstream namespace. Version1.0.0-fil, code10001, Android6+ (API23), target/compile34. APK is universal; inspect actual ABI list and signature with the release tools before distribution. Optional WebRTC native libraries retain their upstream licences; `node scripts/android-license-check.js` checks the resolved runtime classpath against `android/licenses.json`.

`scripts/fil/build-android testDebugUnitTest assembleRelease` uses user-local toolchain paths and private signing.env. No signing secrets or key files belong in Git. The release key must be backed up to owner-controlled separate secure storage before claiming sustainable release handoff. OTA stays OFF until a FIL-only update feed and this certificate are deliberately configured; do not install an upstream APK as an update.

For a selected device only: `adb -s SERIAL install -r /path/FIL-Signage.apk`, open FIL Signage, enter the reachable CMS URL, enter its short-lived pairing code in Devices, assign a published playlist, then apply the profile from the menu editor. Do not reset/root hardware. Device Owner/Lock Task provisioning is optional and model-dependent; a factory reset needs a separate user decision. Screen pinning is not equivalent. Boot autostart, codec smoothness and persistent OS lock require physical tests. The inherited boot/admin/immersive functionality is retained; no manifest-only compatibility claim is made.

Administrator settings use the device's unique six-digit PIN. Five failures lock attempts for30s; state persists across process restarts. Rotate/set the PIN through the existing device admin controls. Never place it in public demo text.

## Backup and restore

`localctl backup` stops only the FIL service, uses SQLite's backup API, archives DB/media/menu packages/JWT/config with checksums and mode0600, then restores the service's previous running state. A cold consistency window avoids racing filesystem media writes. Retain7 daily and4 weekly copies. Same-disk backups are not disaster recovery. Copy encrypted backups and signing material to owner-controlled separate storage when a verified target is available.

`localctl restore ARCHIVE NEW_EMPTY_DIRECTORY` verifies all checksums, SQLite integrity and local media references. It refuses non-empty destinations. Never test restore over production. For rollback: stop FIL only; preserve current data; switch `current` to the previous immutable application release. For schema-incompatible changes restore the matching verified backup into a NEW data directory and update only FIL's environment. Start one writer, verify health/login/media, and retain the failed release and backup for diagnosis.

## Production procedure (requires verified SSH + dedicated DNS)

The templates under deploy/fil are preparation, not evidence of deployment. Verify hostname/host key, architecture, Node version, resources/ports and existing service health before writing. Keep other applications and proxy vhosts intact. No paid infrastructure is created.

1. Package the reviewed clean commit with `scripts/fil/package-server /private/artifacts`. Transfer that immutable archive and checksum through the verified SSH connection. Verify checksum remotely.
2. On the verified VPS, allocate a dedicated non-login user `fil-signage`, release directory `/opt/fil-signage/releases/COMMIT`, data `/var/lib/fil-signage`, and mode0700 config directory `/etc/fil-signage`. Confirm names/paths are unused before creating them. Install dependencies with `npm ci --omit=dev` on that CPU/libc/Node ABI; never copy MINIX node_modules. Use an existing supported Node installation; do not change the global version.
3. Configure the template, keep binding loopback and OTA off. Point `current` to that release; install/start the dedicated service. Bootstrap the first admin through an SSH loopback tunnel before publishing a proxy. An unavailable sudo authority is a blocker, not a reason to alter SSH or privilege policy.
4. Run a first project backup and isolated restore before migration/deployment. Add a project-only daily backup systemd timer using backup.py, service stop/start, a restricted backup directory and the measured disk budget. Monitor timer failures with systemctl/journalctl.
5. Verify the dedicated domain resolves to this VPS. Use the existing certificate/renewal tooling and reverse proxy. Back up only the relevant proxy config; adapt nginx.conf.example; run `nginx -t` before a controlled reload. Never claim TLS with a placeholder hostname. No firewall change should be needed for loopback.
6. Check HTTPS login, upload/download, video Range206, pairing/token isolation, publication state, service restart persistence and pre/post health of unrelated apps. Record actual resource use and hardware state. Keep deployment blocked until the target identity and needed authority are real.

## Updates and quality

Fetch upstream, review commits/releases/security notes and licences, merge into a FIL branch, run focused regressions then the full milestone suite, build/sign locally, back up and migrate, deploy an immutable commit, verify and retain rollback. Never pull upstream main automatically in production. CI uses existing free GitHub-hosted runners; Android checks are manual to avoid rebuilding on documentation pushes. There is no automatic production deployment.

Software/browser/API evidence does not establish tablet/TV codec, autostart, lock-task, one-hour playback or20 physical kiosk transitions. Keep these hardware rows NOT RUN until actually observed.
